- **Signed-in guard (Task 9):** `lib/auth_state.dart` holds a tiny `AuthState` singleton (a `ValueNotifier<bool> signedIn` + `isSignedIn` getter). `main()` seeds it from `FirebaseAuth.instance.currentUser` before `runApp` and keeps it in sync via `authStateChanges()`. The router's `redirect` bounces `state.matchedLocation == '/admin-editor'` visitors to `/` when not signed in — so `/admin-editor` is reachable only after signing in, and logged-out visitors go to the Home screen
- **Admin editor (Task 10):** `/admin-editor` is the **exact Home replica** — N1SK's explicit requirement: nothing changes visually on entry. Both pages render the same shared `lib/widgets/profile_view.dart` (one source of layout, so the editor can never drift from Home). Tap-to-edit only: tapping the cover/avatar opens the image picker (downscaled 1200px cover / 512px avatar, re-encoded JPEG/PNG, uploaded to Storage `images/` as `cover_<millis>.jpg` / `avatar_<millis>.jpg`); tapping the Name/Bio swaps that element in place to an identically-styled TextField (Playball for the name, autofocus, tap-outside to finish; empty bio field shows a "Write a bio…" hint). A **Publish** pill (white, X-style) appears in the **social icons row** (right of the GitHub icon) **only after an actual change** — the dirty check compares controller text to the last-synced value because TextEditingController listeners fire on selection/focus changes too (tapping a field alone must NOT show Publish); while publishing it shows a small spinner. Publish uploads new images then writes `admin/site` (server `updatedAt`); success SnackBar with "View" action → `/`, red error SnackBar on failure. Home reads `admin/site` through `SiteContentState` and updates live. **Empty-bio fix (Task 11):** an empty or missing `bio` in `admin/site` now falls back to the approved placeholder text on both Home and the editor — a blank bio was invisible and untappable, so N1SK couldn't edit it after publishing without one
- **IMPORTANT — Flutter web image fix (Task 10):** uploaded images uploaded fine but never displayed. Root cause: Firebase Storage **media downloads** (`alt=media`) returned no CORS headers, so CanvasKit's `Image.network` (XHR) silently blocked them and the errorBuilder placeholders showed instead. Fixed by setting the bucket CORS policy via the GCS JSON API (PATCH `storage/v1/b`); verified `access-control-allow-origin: *` on media responses. Bucket is **`know-n1sk.firebasestorage.app`** (new-style name, not appspot.com). If images ever stop rendering again, check the bucket CORS config first
- **Social handle links (Task 12):** `SiteContent` carries `facebookUrl` / `xUrl` / `githubUrl` (empty = not set) persisted in `admin/site`. On the admin editor, tapping a social icon opens a popup card — the (non-editable) icon followed by a link text field + Save; saving a link that actually changed closes the popup and reveals the Publish pill; Publish writes the links to `admin/site`. On the public Home page the icons become tappable: `url_launcher` opens the link in a new tab (`webOnlyWindowName: '_blank'`), bare domains get `https://` prepended, icons with no link stay inert, and launch failures are swallowed so a bad link never breaks the page. `ProfileView` exposes an `onSocialTap(String)` hook — the editor passes it (popup), Home leaves it null (launch)
